The problem

Long campaigns deserve better than scattershot notes

Experienced DMs on Discord know the pain: the story is rich, the table is invested—and continuity lives in twelve places, none of them trustworthy.

Forgotten NPCs

Names, motives, and half-finished favors vanish between sessions. The table notices before your notes do.

Lost plot threads

Open questions scatter across chat history, voice notes, and “we’ll get back to that.” Months later, nobody owns the thread.

Inconsistent notes

External docs drift from what Discord already said. Two truths appear—and neither is sealed.

Bookkeeping killjoy

Post-session write-ups steal the high of a great night. Momentum dies in a blank document.

Your campaign already has a truth. GlyphKeeper keeps it sealed—and available at the table.

How GlyphKeeper works

From channel bind to grounded summary

A clear loop for live play: bind the campaign, run the session, ask grounded questions, keep memory under your control.

  1. 01

    Bind a campaign to a Discord channel

    Create the campaign where you play. That channel becomes the scoped home for every record and every answer.

    /campaign create
  2. 02

    Start a session

    Open play mode when the table sits down. Co-pilot turns and durable extraction stay tied to the active session.

    /session start
  3. 03

    Ask by mentioning the bot

    Answers combine authoritative campaign records, campaign-scoped semantic recall, and light conversational context—never free invention of canon.

  4. 04

    Automatic durable event extraction

    Important beats can be stored with importance and confidence thresholds. Known names normalize to their canonical campaign spelling. Low-value noise is dropped.

  5. 05

    Inspect, edit, forget, or regenerate

    Browse the timeline, recall by meaning, correct text, link characters and locations, preview deletions, and rebuild summaries from stored truth.

  6. 06

    End session → grounded summaries

    Session and campaign summaries use only authoritative stored data—recap, key outcomes, and active threads you can trust next week.

    /session end

Core capabilities

Memory tools built for the table that already exists

Continuity without the bookkeeping burden—and without handing the story to a chatbot that freestyles your world.

Grounded memory & semantic recall

Campaign records are the source of truth. Semantic search stays campaign-scoped so answers pull from your history—not a generic model’s imagination.

Durable event extraction

Importance and confidence filtering keep junk out of canon. Entity names normalize to the spellings already stored for the campaign.

Full memory toolkit

Timeline, recall, edit, forget (preview then confirm), and link or unlink characters and locations. Repair drift without rewriting history by hand in a wiki.

Grounded session & campaign summaries

Summaries only use authoritative stored data—structured recap, key outcomes, and active threads. Regenerate when records change; the fiction stays honest.

Co-DM allowlist

Owners manage who can mutate durable memory. Co-DMs share the load; the public table can still inspect continuity without rewriting it.

Local-first with Ollama

Chat and embeddings run on your machine through Ollama. No cloud LLM required for the co-pilot path. Your inference stays home.

Command surface

Slash commands that respect the table

Mutations stay protected. Inspection stays open. Here’s a taste of the surface—not the full manual.

Permissions at a glance: Public — inspect Mutator — owner or Co-DM Owner — Co-DM allowlist
/campaign create

Channel Become owner & bind the campaign

/session start

Mutator Open the active play session

/session end

Mutator Save grounded summaries & close session

/memory recall

Public Semantic search over campaign events

/memory timeline

Public Browse recent events newest-first

/memory edit

Mutator Correct event text; refresh search vectors

Mutator Preview matches, then confirm delete

/codm add

Owner Authorize a Co-DM on the allowlist

Mutations reply ephemerally. Unauthorized users hear a clear “owner required” or “owner or Co-DM required”—not a vague failure.

Philosophy

Not an AI DM. Not another notebook.

GlyphKeeper sits where long-running Discord tables actually need help: live presence, trusted structure, and human control.

Full AI Dungeon Masters

Invent & take over

They generate plot, play NPCs as gospel, and slowly replace the human’s creative authority. Fun as toys—dangerous as campaign truth.

Pure note-taking tools

Outside the table

Wikis and docs live away from Discord. They don’t hear the session, don’t stay grounded in play, and drift the moment you’re tired.

GlyphKeeper

Live Discord + sealed memory

Co-pilot in the channel. Structured records as authority. Owner and Co-DMs decide what endures. The human DM stays sovereign.

  • Memory is the source of truth. The model narrates around retrieved state; it does not invent canon.
  • The bot is a co-pilot—a continuity engine, never a replacement for the person running the game.
  • Owner + authorized Co-DMs retain explicit control over durable memory.
  • Continuity without burden. Long campaigns feel personal and continuous so you can focus on the table.

Not a replacement DM. Not another notebook that forgets what Discord already said. Continuity you can trust.

Requirements

Getting started

GlyphKeeper runs on your Windows machine as a Discord bot with local models and a Supabase-backed memory store.

Windows 10 / 11 Node.js 24+ Discord bot + Message Content Intent Supabase project Ollama + local chat & embedding models

One-line setup flow

Clone → configure .env → pull Ollama models → apply Supabase migrations → run the bot.

Keep the host awake and online while you play: Ollama and GlyphKeeper both run locally. “Local-first” means inference and bot hosting on your machine; durable campaign records live in your Supabase project.
